# Contributing to Awesome Hypereffect

Thanks for helping make this list better. Please keep contributions small and focused.

## What belongs here

An entry should be one of:

- the hypereffect protocol itself or one of its official implementations;
- a renderer that displays hypereffect applications;
- a tool or server built with hypereffect;
- an application, protocol, or service that uses or extends hypereffect;
- documentation, a specification, or a learning resource.

Projects must be publicly available and maintained. Archived projects, dead links, and pure marketing pages are not accepted.

## Adding an entry

1. Add one item per pull request.
2. Put it in the most relevant section.
3. Use this format:

   ```markdown
   - [Name](https://example.com) - A short, factual description that ends with a period.
   ```

4. Start the description with a capital letter and keep it to one sentence where possible.
5. Do not use marketing language, superlatives, emoji, or trailing punctuation other than the final period.
6. Link to the canonical repository or website, not to a mirror.
7. Run the link check or open each link yourself.

If you are adding a sub-item, such as a tool inside a collection, link directly to that tool and keep it in the collection's sub-list.

## Style

- Keep the existing section order and heading levels.
- Use sentence case for headings.
- Use one blank line between sections and list items.
- Prefer `https://` links.
- Do not add a table of contents entry manually; update the existing one if you add a top-level section.

## Reporting problems

Open an issue with the name of the entry and what is wrong (dead link, outdated description, project archived, and so on). Small fixes can go straight to a pull request.
